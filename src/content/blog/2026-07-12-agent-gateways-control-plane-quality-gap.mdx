Three enterprise products launched in three days.

On July 2, Manufact opened its MCP hosting cloud to production — one push from GitHub repo to monitored endpoint. On July 3, [Arcade dropped its agent authorization and tool-execution runtime onto the Azure and AWS marketplaces](https://www.forbes.com/sites/janakirammsv/2026/07/05/agent-gateways-are-becoming-the-control-plane-for-enterprise-ai/), where enterprises can deploy it against existing cloud spend with one click. The same week, [Nutanix made its Agent Gateway generally available](https://www.nutanix.com/blog/introducing-nutanix-agent-gateway) as part of Nutanix Enterprise AI 2.7 — a centralized control point for managing traffic from agents to LLMs and from agents to every business tool they call.

[Forbes framed all of it clearly](https://www.forbes.com/sites/janakirammsv/2026/07/05/agent-gateways-are-becoming-the-control-plane-for-enterprise-ai/): agent gateways are becoming the control plane for enterprise AI. Google agrees — its Gemini Enterprise Agent Platform is built around exactly this stack: Agent Identity, Agent Gateway, Agent Registry. A wave of specialist vendors (Saviynt, Silverfort, TrueFoundry) is selling the same governance layer for organizations that want it independent of any single cloud provider.

The Kubernetes parallel is the one everyone's reaching for, and it's the right one. Which is exactly why it should make you nervous.

## What Agent Gateways Actually Do

The analogy to Kubernetes is clean enough to be useful. Kubernetes solved the orchestration layer for containers: scheduling, networking, routing, resource limits, rollback. It gave operators visibility into what containers were running and control over how they behaved. Before Kubernetes, containers were genuinely hard to manage at scale. After, the operational layer was largely a commodity.

Agent gateways are doing the same thing one layer up. The [Nutanix Agent Gateway](https://www.sdxcentral.com/news/nutanix-targets-enterprise-ai-wallet-bleed-with-agent-control-plane/) targets what Nutanix calls "wallet-bleed" — the ungoverned token spending that happens when dozens of agents make unconstrained API calls. It provides token routing, observability, rate limiting, MCP server governance. [Arcade comes at it from authorization](https://www.forbes.com/sites/janakirammsv/2026/07/05/agent-gateways-are-becoming-the-control-plane-for-enterprise-ai/), giving background agents delegated user authority that gets re-checked at the moment of every action. The pattern across all three major cloud providers is converging on the same control plane shape: agent identity, a traffic router, a policy enforcement layer, and a registry of what's running.

This is real infrastructure. It solves real problems. Ungoverned AI agent sprawl is [a documented crisis](https://aiagentstore.ai/ai-agent-news/this-week): [OutSystems found that 94% of enterprises report AI sprawl increasing complexity, security risk, and technical debt](https://www.outsystems.com/news/enterprise-ai-agent-report-2026/), and IBM projects large enterprises will average over 1,600 deployed agents by year-end with most unable to inventory what they're actually running. A control plane that routes traffic, enforces auth, manages costs, and logs activity is not optional infrastructure. It's overdue.

But here's the thing Kubernetes taught us, and the thing the agent gateway wave is quietly inheriting.

## Kubernetes Tells You What Is Running, Not Whether It's Good

Kubernetes is excellent at scheduling containers. It has no opinion on whether those containers are doing their jobs correctly.

This is not a critique of Kubernetes. It was never designed to answer that question. The answer to "is this service performing well?" lives in APM tools, distributed tracing, load testing, feature flags, canary deployments — a whole separate instrumentation layer that had to be built on top of, not instead of, the orchestration layer.

Agent gateways are exactly the same shape. They tell you which agents are running, what tools they're calling, how many tokens they're consuming, whether they're staying within policy bounds. They do not tell you whether the agents are actually performing well at their tasks — whether task completion rates are acceptable, whether output quality matches what was validated pre-deployment, whether the agent you're running is any better than a competing agent on the same work.

Governance answers: *is this agent allowed to do what it's doing?*

Verification answers: *is this agent good at what it's doing?*

The gateway wave solves governance. The verification layer is the one that hasn't shipped.

## The Instrumentation Trap

The risk is the one that played out after Kubernetes. Once you have a clean control plane, you feel like you have visibility. The dashboards fill up with data — requests routed, tokens consumed, tools called, rate limits hit. The data is real. The sense of control it creates is partially illusory.

[Sinch's AI Production Paradox report](https://sinch.com/news/sinch-releases-ai-production-paradox/) surveyed 2,527 enterprise decision-makers and found 74% of live production AI agents have been rolled back. The leading cause was not a governance failure. It was operational failure: data exposure, inconsistent outputs, behavior that diverged from what evaluation environments predicted. The agents were within policy the whole time. They were just bad at the task.

Monitoring tells you something went wrong. A gateway tells you it happened. Neither tells you what the agent's correct behavior looked like in the first place — because that requires a task-level performance baseline defined before production, not discovered by watching the logs fill up after deployment.

The [Gartner prediction that 40% of agentic AI projects will be canceled by end of 2027](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027) wasn't made about agents operating outside governance rails. It was made about agents that couldn't demonstrate business value or adequate risk controls. Governance-compliant agents. Well-routed agents. Agents whose token spend was fully visible and their tool calls fully logged.

Agents nobody could prove were any good.

## What Comes After the Gateway

The control plane era is healthy and necessary. It's the right thing to build. Every enterprise running a hundred agents needs centralized routing, auth, and cost visibility before it needs anything else — and that layer is now commoditizing fast. In two years it'll be boring infrastructure the same way Kubernetes is now.

What fills in next is the quality layer. Task-level performance baselines before production. Comparative benchmarking on the organization's actual workload distribution, not vendor-published synthetic evaluations. Continuous monitoring against those baselines as models update, data drifts, and scope expands. The ability to answer, for any agent in production: what is this agent supposed to be achieving, and is it achieving it?

The gateway gives you the nervous system. It tells you what agents are doing. The quality layer is the immune system — the infrastructure that tells you whether what they're doing is any good.

The industry built the nervous system first. That was the right sequence. The immune system is the next race.
