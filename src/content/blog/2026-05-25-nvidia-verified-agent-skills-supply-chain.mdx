Three days ago, NVIDIA [shipped Verified Agent Skills](https://developer.nvidia.com/blog/nvidia-verified-agent-skills-provide-capability-governance-for-ai-agents/) — a framework that scans, signs, and documents agent skill packages before they reach a production deployment. The announcement landed quietly compared to NVIDIA's typical product launches. It shouldn't have.

The framework introduces [SkillSpector](https://github.com/NVIDIA/skills), a scanning tool that runs each skill through a two-phase check before it can be listed in NVIDIA's verified catalog. Phase one is conventional software security: vulnerable dependencies, suspicious scripts, dangerous code patterns, credential harvesting, and data exfiltration paths. Phase two is what's new — agent-specific threat detection: hidden instructions, prompt injection payloads, trigger abuse, excessive agency requests, tool poisoning, and mismatches between what a skill declares it does and what it actually does.

Every skill that clears both phases gets a cryptographic signature and a Skill Card — a machine-readable document specifying ownership, dependencies, declared limitations, and verification status. The cards follow the [agentskills.io open specification](https://agentskills.io), designed to be portable across Claude Code, Codex, and Cursor.

This matters. Here's why, and here's where it stops.

## The npm Moment for Agent Skills

If you've been in software long enough to remember 2016, you remember [left-pad](https://qz.com/646467/how-one-programmer-broke-the-internet-by-deleting-a-tiny-piece-of-code). A developer unpublished a small npm package — 11 lines of code — and broke the builds of thousands of applications that depended on it transitively. The incident wasn't a security attack. But the structural vulnerability it exposed was the same one that later fueled a wave of deliberate supply chain attacks through malicious npm packages.

The agent skill ecosystem is running the same playbook npm ran in 2012: move fast, build a large catalog of composable packages, optimize for developer velocity, and defer the trust question until something goes wrong.

The specific risks SkillSpector addresses aren't hypothetical. A third-party agent skill that contains hidden instructions can silently redirect your agent's behavior — telling it to favor certain vendors, exfiltrate request patterns, or activate differently when triggered by specific inputs the developer never sees in testing. Trigger abuse and tool poisoning are harder to catch than conventional malware because they don't exploit system vulnerabilities — they exploit the agent's instruction-following behavior, which is the feature, not a bug.

NVIDIA publishing both the verification framework and the skill catalog with cryptographic signing is the first serious attempt to bring trust infrastructure to this ecosystem. The alternative — an unverified market of third-party skills that any agent can consume without scrutiny — is the attack surface that's been sitting open since the first agent marketplace launched.

## What Skill Verification Is, and Isn't

Here's the precise scope of what a verified skill card tells you:

It tells you the skill is what it claims to be. It hasn't been tampered with since NVIDIA signed it. Its declared behavior matches its actual code at the time of signing. It doesn't contain known agent-specific attack patterns.

It doesn't tell you whether the skill makes your agent better at your task.

That distinction is not a nitpick. An agent skill for, say, financial document summarization can pass every SkillSpector check — no hidden instructions, no tool poisoning, clean dependencies, cryptographically signed — and still produce summaries that are accurate 60% of the time on the documents your agents actually process. The skill is safe. It might not be good.

Security verification and performance verification address different threat models. SkillSpector catches *malicious* behavior and supply chain compromise. It was never designed to catch *mediocre* behavior or domain-specific failure modes, and it can't — those require evaluation against real task distributions, not static code analysis.

## The Stack Being Built

NVIDIA's announcement fits into a broader pattern of the industry building trust infrastructure layer by layer.

[A2A](https://www.prnewswire.com/news-releases/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year-302737641.html) solved agent-to-agent identity and communication — the networking layer. [Microsoft Agent 365](https://www.microsoft.com/en-us/security/blog/2026/05/01/microsoft-agent-365-now-generally-available-expands-capabilities-and-integrations/), now generally available, added governance and observability — the control plane layer. [Visa's Trusted Agent Protocol](https://www.pymnts.com/visa/2026/visa-wants-to-make-ai-shoppers-as-trusted-as-human-ones/) addressed authentication for agentic commercial transactions — the payments trust layer. NVIDIA's Verified Skills now address supply chain integrity for skill packages — the provenance layer.

Each of these layers is real and needed. Together they solve for: *can this agent communicate securely, can I observe and control it, is it actually who it says it is, and does its skill package come from a trustworthy source?*

What they don't solve collectively: *does this agent actually do the work correctly?*

That question sits outside the scope of all four layers, and it's the one that determines whether an agent deployment succeeds or ends up in [Gartner's 40% cancellation forecast](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-of-agentic-ai-projects-will-be-canceled-by-end-of-2027).

## The Gap in the Stack

The 37% spread between agent benchmark performance and production performance that's been [documented across enterprise deployments](https://www.technologyreview.com/2026/04/13/1135675/want-to-understand-the-current-state-of-ai-check-out-these-charts/) isn't a security problem. It's an evaluation problem. The skill passed all the checks. The agent deployed. The outputs were worse than expected because the evaluation was designed to catch tampering, not mediocrity.

Every layer that's been built in the last twelve months has been a security or governance layer — things that are genuinely important, that needed to be built, and that address real risks. The performance layer, the one that answers whether the agent is actually reliable at the specific tasks in your specific environment, is what's still missing from the stack.

NVIDIA's verified skills catalog currently lists 161 skills across 16 product areas. When that catalog grows to 1,600 skills from dozens of contributors, the SkillSpector output will tell you which ones are trustworthy in the security sense. The procurement question — which of these 1,600 verified skills actually works for what I'm building — will still need an answer.

That answer requires the same thing it's always required: running the agent against representative tasks, measuring the outcomes, and knowing the performance profile before the deployment decision. The cryptographic signature tells you the skill hasn't been poisoned. Your benchmark tells you whether it's any good.

Both layers are necessary. The industry has now shipped most of the first. The second is where the work is.
