Salesforce co-founder Parker Harris put the question plainly at [Dreamforce 2026](https://www.salesforce.com/news/stories/five-dreamforce-2026-takeaways/): Do you even need to log into Salesforce anymore?

His answer, embedded in the [AIforce announcement](https://www.salesforce.com/news/stories/aiforce-announcement/), is effectively no. The UI is a rendering choice. The real product has always been the platform — the data, metadata, workflows, business logic, permissions, and security that enterprises have been building in Salesforce for two decades. The dashboard was just the window you looked through. AIforce removes the window requirement.

What launched at Dreamforce is an interface layer — previously called [Headless 360 before its September rebranding](https://www.salesforceben.com/comparing-salesforces-aiforce-headless-360-and-the-enterprise-ai-harness/) — that exposes Salesforce capabilities as an MCP server. Any authorized AI agent can discover and invoke those capabilities directly: pull opportunity data, close a case, update a forecast, route an escalation. The first implementations — [Claudeforce and Slackforce](https://www.concret.io/blog/dreamforce-2026-keynote-day-1) — put Claude and Slack's interfaces in front of Salesforce's platform. Soon, any agent with proper permissions does the same thing.

That's a genuine architectural insight with real consequences. It also creates a measurement problem the enterprise software industry has never had to solve before.

## The UI Was Actually Doing Measurement Work

Here's what gets lost when the interface layer goes headless.

Enterprise software UIs are terrible for a lot of reasons — slow, rigid, built for processes that calcified years ago. But they do one thing quietly and well: they constrain the action space. You click on the Opportunity Stage dropdown. The options are Prospecting, Qualification, Proposal, Negotiation, Closed Won, Closed Lost. You cannot type "looks promising" into the stage field. The UI enforces vocabulary, path, and structure by the nature of what it renders.

UX research — conversion analysis, error rate tracking, time-on-task measurement, A/B testing — works because the interface defines a bounded interaction surface. You can measure what percentage of reps update stage within 24 hours of a customer call because the UI emits events, and those events have a consistent semantic meaning. You can tell when a user got stuck because they didn't advance through the workflow.

AI agents don't work that way. An agent interpreting a natural language request to "update the deal with Acme" brings its own judgment to every step: which record to retrieve, which fields to interpret as relevant, which action to take, whether to confirm. Two agents given identical instructions in the same environment will make different decisions. One will close the right opportunity and move it to Negotiation. Another will update the wrong contact record and mark the company as inactive.

The UI never hallucinated. The agent might.

## The New Interface Question Is an Evaluation Question

Before AIforce, the enterprise software selection question was: which vendor's platform has the best UI for my workflows? Usability tests answered it. User satisfaction surveys answered it. Salesforce won, in part, because its interface was better than SAP's.

After AIforce, the question changes. If the platform is Salesforce, and any agent can access it, then the differentiating variable is the agent. Which agent is most reliable for updating CRM records from unstructured call notes? Which one is most accurate when routing cases from a customer description to the correct support tier? Which one fails least often when interpreting ambiguous instructions about a multi-step sales workflow?

These aren't UX questions. They're performance benchmarking questions.

The problem is that the enterprise world has decades of tooling for the first kind of question and almost none for the second. You can run a usability study. You can A/B test a button placement. You cannot easily A/B test whether Claude's completion rate on Salesforce case routing outperforms a fine-tuned open-source model on your actual support ticket distribution — at least not without purpose-built evaluation infrastructure.

[Gartner predicts over 40% of agentic AI projects will be canceled by end of 2027](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027), citing unclear business value and inadequate risk controls as the primary causes. The unclear business value problem, in an AIforce world, is an evaluation infrastructure problem. The enterprise deployed an agent against their Salesforce environment. They don't know if it's doing the work well. They can tell it's running. They can't tell if it's right.

## What This Shift Requires

The enterprises that extract value from the AIforce model — and from the broader shift toward agents-as-interfaces it represents — will not be the ones with the most agents deployed. They'll be the ones that build evaluation infrastructure before deployment rather than after the first failure.

That means treating agent selection with the same rigor that once went into software selection. Before committing an agent to your CRM workflows, run it against a representative sample of your actual task distribution: the cases your support agents handle, the opportunities your sales ops team updates, the forecasts your finance team pulls. Measure completion rate, error rate, and failure modes. Compare it against alternatives on your specific data, not the vendor's synthetic benchmark.

[Fewer than 10% of enterprises that have experimented with AI agents have scaled them to deliver measurable value](https://everywan.com/en/blog/enterprise-ai-agents-40-percent-canceled), with poor data quality and governance cited as the primary barriers. Governance infrastructure is getting built — Microsoft's ACS, Salesforce's own Zero Data Retention commitment in AIforce. The measurement layer is the next gap. When agents replace UIs as the primary interface to business-critical platforms, the old usability research playbook doesn't transfer. The question becomes: does this agent reliably complete the work?

## The Architectural Insight That Changes the Question

Salesforce is right about the underlying architecture. The platform — the 20 years of CRM data, business rules, workflow automation, permissions models, security policies — is the product. The browser-and-click interface was always a rendering detail. Making the platform available to AI agents directly is the logical next step.

But recognizing that the UI is optional doesn't make the agent's judgment optional. The UI constrained choices. The agent makes them. And enterprise decisions — routing a support escalation, updating a revenue forecast, classifying a customer complaint — need to be made correctly at high rates before they're safe to delegate.

Parker Harris asked the right question. Do you even need to log in? You probably don't. But before you hand the keys to any agent that can invoke Salesforce through AIforce, you should know how that agent performs on the actual work your business depends on.

The dashboard wasn't the product. The agent that replaces it still has to earn its job.
