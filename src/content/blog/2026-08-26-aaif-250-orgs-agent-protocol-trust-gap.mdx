On August 20, [Google formally transferred the Agent2Agent (A2A) protocol to the Agentic AI Foundation (AAIF)](https://www.techzine.eu/news/devops/143659/google-transfers-a2a-to-the-agentic-ai-foundation/), the Linux Foundation-directed body that already governs Anthropic's Model Context Protocol (MCP). In a single move, the two protocols that define how AI agents communicate — A2A for agent-to-agent coordination, MCP for agent-to-tool integration — landed under one neutral governance umbrella with more than 250 member organizations: AWS, Anthropic, Google, Microsoft, OpenAI, Bloomberg, Cloudflare, Block, Shopify.

That's the protocol wars ending.

The same week, [Deloitte published its 2026 AI readiness survey](https://www.deloitte.com/us/en/about/press-room/deloitte-survey-examines-ai-readiness-agentic-ai-success.html) with a number that should follow the AAIF announcement into every board deck: only 20% of organizations are prepared for autonomous AI agents. Governance readiness specifically sits at 30%. Technical infrastructure is at 43%. Five percent say they're highly prepared.

Seventy-four percent of leaders in that same survey expect nearly half their business processes to be redesigned around AI agents within four years.

The protocol layer was built in under a year. The governance layer is at 30%.

## Why the AAIF Milestone Actually Matters

The consolidation of A2A and MCP under one foundation isn't just symbolism. It closes the last meaningful question about what agents use to talk to each other.

Before this, A2A and MCP were under separate stewardship — both growing fast, both with major enterprise adoption, but technically under the control of their originating companies. [AAIF's formation in December 2025](https://aaif.io/blog/a2a-joins-aaif) brought MCP into a neutral home. A2A's transfer completes the picture: both protocols are now governed by a structure that any organization can participate in, contribute to, and rely on without a vendor dependency.

For practitioners, this settles something that enterprise architects have been quietly anxious about for eighteen months: what if one of these protocols gets controlled or deprecated by its originating company? That risk is gone. The stack is neutral, the governance is distributed, and with 250 members committing to both protocols, the network effects are past the point of reversal.

This is genuinely good news. The agent internet now has a settled plumbing layer — one protocol for how agents hand tasks to each other (A2A), one for how agents interact with tools and data sources (MCP), and a foundation that neither Google nor Anthropic can unilaterally change. Build on it with confidence.

## What It Doesn't Settle

A2A and MCP specify the *format* of communication. They say nothing about whether you should trust what's being communicated.

When an orchestrator reads an A2A agent card, it learns what capabilities the agent claims to have. It does not learn whether the agent has been independently benchmarked. It does not learn the agent's real-world failure rate on tasks similar to yours. It does not learn whether the agent's published performance numbers came from a controlled evaluation or a cherry-picked demo. The card is a declaration. The verification isn't there because the protocol was never designed to carry it.

This is the same architectural gap the web hit after HTTP: the protocol gets you to any server, but it doesn't tell you whether the server is any good. The web solved that layer with certificate authorities, reputation systems, search ranking, and eventually app store review. None of those came from the HTTP specification. They were built on top.

The agent internet needs the same layer. And the Deloitte data describes exactly what happens when you try to scale deployment without it.

## The Gap Between Deploying and Trusting

Thirty percent governance readiness means seven in ten enterprises are deploying agents without the organizational infrastructure to know whether those agents are working.

That's not ignorance of the problem — the same Deloitte survey found that 74% of leaders expect to redesign half their processes around agents in four years. They're not moving slowly. They're moving fast without the measurement layer.

What governance readiness actually requires, according to Deloitte's own framing: current inventory of what agents are running, performance baselines by task type, process for evaluating new agents before deployment, mechanism for comparing agent alternatives on the same workloads. Most organizations have none of these. They have agents in production, a vague sense that things are working, and quarterly reviews that nobody connects to operational agent data.

The $85 million raised by [Obsidian Security this month at a $1.1 billion valuation](https://aiagentsdirectory.com/news/ai-agents-news-brief-august-21-2026) — specifically for monitoring AI agents interacting with enterprise data — signals that the security dimension of this gap is attracting capital. Security is one axis. Performance and trustworthiness are another, and they're harder to instrument because they require knowing not just *what* the agent did, but *how well*.

## The Speed Comparison Is Uncomfortable

Here's the number that should bother anyone shipping agents right now.

The industry built the protocol layer — from Google's A2A proposal to 250 organizations under neutral governance — in roughly nine months. That's a remarkable coordination achievement across competitors. AWS, Microsoft, Google, and Anthropic do not agree on much. They agreed on this.

Governance readiness is at 30% despite enterprise AI being a multi-year industry initiative with enormous organizational attention. The problem isn't that governance is hard. It's that governance doesn't ship on a deadline and protocol does.

Protocols have specifications. You implement to spec, pass conformance tests, and you're done. Governance is messier — it requires measurement systems, baseline data, organizational processes that outlast quarterly planning cycles, and tooling that connects to real task outcomes rather than compliance checkboxes.

AAIF's announcement is effectively a starting gun for the governance layer. The protocol question is answered. The infrastructure question — how do you actually know whether the agents running on that protocol are performing well enough to be trusted with your operations — is the one that determines whether the deployment boom compounds or collapses.

## What Gets Built Next

The MCP/A2A stack gives every agent a common format for announcing what it can do. The next infrastructure layer embeds verification into those announcements: independent benchmark results, adversarial test outcomes, task-level reliability scores drawn from real production data, and comparative ratings against agents doing similar work.

An orchestrator routing tasks across an A2A network shouldn't have to guess which agent is most trustworthy. It should be able to read that from the agent card, the same way a browser reads a TLS certificate. Not "this agent claims to handle financial reconciliation" — "this agent claims to handle financial reconciliation, here's a third-party verified score from 10,000 production tasks, here's how it ranked against three comparable agents on the same benchmark set, and here's when those scores were last validated."

That's the infrastructure that makes governance readiness go from 30% to something worth relying on. The protocol layer is done. That's a genuine achievement. Now the same organizations that coordinated to solve the communication problem need to coordinate — or someone needs to build the infrastructure without their permission — to solve the verification problem.

Nine months from proposal to neutral governance for the protocol layer.

The governance layer is already overdue.
